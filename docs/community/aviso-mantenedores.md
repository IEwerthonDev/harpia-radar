# Modelo de aviso para quem mantém os projetos

A spec pede uma issue **escrita à mão, uma por projeto**, depois que a página estiver no ar. Use este texto só como ponto de partida e personalize cada uma: cite algo concreto do projeto e os selos atuais dele.

Se o repositório não aceita issues, use Discussions; se também não houver, não avise.

---

**Título:** O <projeto> está no Harpia Radar 💚

Olá! Sou da comunidade Harpia, um grupo brasileiro de código aberto.

Criamos o [Harpia Radar](https://iewerthondev.github.io/harpia-radar/), uma página que acompanha os projetos abertos de que o Brasil depende, e o <projeto> está na lista porque <motivo concreto: ex. "muita gente emite NF-e com ele">.

A página mostra dois selos, calculados todo dia a partir da API pública do GitHub:

- Atividade: <selo atual>
- Sustentação: <selo atual>

Queria deixar claro o espírito da coisa: **não é ranking nem avaliação de qualidade**. A ideia é mostrar onde a comunidade pode ajudar e trazer gente nova para projetos que fazem diferença. A página não mostra nome de ninguém, só números agregados.

Se quiser que o projeto saia da lista, que a descrição mude ou que a gente divulgue alguma issue para quem quer começar, é só responder aqui ou abrir um PR em https://github.com/IEwerthonDev/harpia-radar.

Obrigado pelo trabalho! 🙌

---

Antes de publicar, confira os selos atuais do projeto na página e ajuste o texto. Para projetos com "Precisa de mãos", evite qualquer frase que soe como cobrança.

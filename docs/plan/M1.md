## Endpoints (por projeto)

1. `GET /repos/{o}/{r}`: `archived`, `license.spdx_id`, `open_issues_count`.
2. `GET /repos/{o}/{r}/commits?per_page=1`: data do último commit (`commit.committer.date`).
3. `GET /repos/{o}/{r}/releases/latest`; se 404, `GET /tags?per_page=1` e `GET /commits/{sha}` para a data da tag.
4. `GET /repos/{o}/{r}/commits?since=...&per_page=100`, seguindo o cabeçalho `Link: rel="next"`.

Retry: `RetryableHttpClient` do symfony/http-client (3 tentativas em erro de rede, 429 e 5xx, respeitando `Retry-After`).

## Decisões fora da spec

- Data do commit = data do committer (quando entrou na branch), em UTC.
- Tag mais recente = primeira tag devolvida pela API (o GitHub ordena por nome/versão, não por data); buscar a data de todas as tags custaria muitas requisições.
- `open_issues` vem de `open_issues_count`, que no GitHub inclui PRs abertos. A página não mostra esse número.
- `top_author_share` arredondado em 4 casas.
- Licença `NOASSERTION` (licença não reconhecida pelo GitHub) é gravada como veio.
- Repositório sem nenhum commit vira `status: error`.
- Falha que afeta todos (token recusado, limite da API) interrompe a coleta sem gravar.

## Configuração manual (uma vez)

1. GitHub → Settings → Pages → Source: **GitHub Actions**.
2. GitHub → Settings → Actions → General → Workflow permissions: **Read and write**.
3. Se a `main` tiver proteção de branch, permitir que o `github-actions[bot]` faça push do snapshot (ou o commit diário falha).
4. Codeberg (opcional): criar o repositório (`spiralout/harpia-radar`), gerar um token com escopo de escrita em repositórios e cadastrar no GitHub:
   - segredo `CODEBERG_TOKEN`
   - variável `CODEBERG_REPOSITORY` = `spiralout/harpia-radar`

   A página fica em `https://spiralout.codeberg.page/harpia-radar/`.

## Decisões fora da spec

- Horário: 05:23 UTC (minuto quebrado evita a fila do horário cheio do Actions).
- O workflow também roda em push na `main` quando muda lista, config, templates ou código, para a página refletir a mudança no mesmo dia.
- A checagem de acessibilidade bloqueia a publicação: se a página nova falhar, a anterior continua no ar.
- Dependabot semanal para Composer e Actions, agrupado em um PR por ecossistema.
- O snapshot muda todo dia (`generated_at`), então há um commit de dados por dia. É o histórico pedido no RF-04.

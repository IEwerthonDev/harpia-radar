# Plano do M0 — Base

Status: **implementado**, aguardando aprovação da entrega.

## Requisitos cobertos

| ID | O que entra no M0 |
| --- | --- |
| RF-01 | `CatalogLoader` lê `projects.yaml`; `validate` falha dizendo o projeto e o campo quando falta um obrigatório. A parte "o coletor processa os N" fica pronta do lado do loader (devolve N projetos); o coletor em si é M1. |
| RF-07 | `bin/radar validate`: schema, IDs únicos (projetos e categorias), categoria existente e repositório acessível. Workflow `.github/workflows/validate.yml` rodando em PRs que alteram `projects.yaml`. |
| RNF-02 | Mensagens do `validate` em português; código, chaves e valores em inglês. |
| RNF-07 | Testes sem rede: checagem de acesso ao repositório testada com `MockHttpClient` e respostas gravadas em `tests/fixtures/github/`. |
| RNF-08 | `LICENSE` MIT já existe. |

Também entram, porque o M0 os pede explicitamente: `schema/snapshot.schema.json` (usado de verdade a partir do M1) e `config/health.yaml` (usado a partir do M2), mais um schema para validar o próprio `health.yaml`.

## Formato proposto

**config/health.yaml**

```yaml
window_days: 90
activity:
  release_max_age_months: 12
sustainability:
  min_commits: 10            # abaixo disso: insufficient_data
  well_distributed_bus_factor: 3
  few_people_bus_factor: 2
  max_top_author_share: 0.75 # acima disso: needs_hands
bots:
  suffix: "[bot]"
  logins: [dependabot, renovate]
```

**Valores de `health` no snapshot** (enums do schema; a spec só cita `active` e `needs_hands`):

- `activity`: `active`, `active_no_recent_release`, `no_recent_changes`, `archived`
- `sustainability`: `well_distributed`, `few_people`, `needs_hands`, `insufficient_data`

**Projeto com erro no snapshot**: `{"id": "...", "status": "error", "error": "<mensagem>", "metrics": null, "health": null}`.

**Métricas sem commits na janela**: `top_author_share` e `bus_factor` ficam `null`; `last_commit_at` continua preenchido.

## Testes que provam cada critério de aceite

| Critério | Teste |
| --- | --- |
| RF-01: YAML válido com N projetos → N processados | `CatalogLoaderTest`: fixture com 3 projetos devolve 3; o `projects.yaml` real devolve 9 |
| RF-01: campo obrigatório ausente → falha dizendo projeto e campo | `ValidateCommandTest`: um caso por campo obrigatório (`id`, `name`, `repo`, `category`, `description`); saída contém o id do projeto (ou o índice, quando falta o próprio `id`) e o nome do campo; exit code 1 |
| RF-07: schema | `SchemaValidatorTest`: id fora de kebab-case, `repo` sem prefixo, campo desconhecido, tipo errado |
| RF-07: IDs únicos | `CatalogValidatorTest`: projeto duplicado e categoria duplicada |
| RF-07: categoria existente | `CatalogValidatorTest`: projeto apontando para categoria não declarada |
| RF-07: repositório acessível | `GitHubRepositoryProbeTest`: 200 → ok; 404 → erro com nome do repo; 401/403 → erro de token; timeout → erro; header `Authorization` presente |
| Token obrigatório | `ValidateCommandTest`: sem `GITHUB_TOKEN`, falha com mensagem clara antes de qualquer requisição |
| Todos os erros de uma vez | `ValidateCommandTest`: YAML com 3 problemas lista os 3, não para no primeiro |
| Arquivos do repositório coerentes | `RepositoryFilesTest`: `projects.yaml`, `config/health.yaml` e um snapshot de exemplo passam nos schemas |

## Decisões

| # | Tema | Decisão |
| --- | --- | --- |
| 1 | Local da spec | Movida para `docs/SPEC.md` (feito). |
| 2 | Versão do PHP | **Diverge da spec (8.3).** PHP 8.5, a versão estável atual (8.5.12, de 21/10/2026). `composer.json` exige `^8.5`; CI usa 8.5. Localmente, roda via Docker (`php:8.5-cli` + Composer), sem instalar nada no WSL. A hospedagem não muda: a página é HTML estático no GitHub Pages, e o PHP só roda no GitHub Actions. |
| 3 | Token no `validate` | `validate` sempre exige `GITHUB_TOKEN`. A opção `--offline` não foi confirmada e não foi criada. |
| 4 | Categorias | As seis do objetivo 2, com ids em inglês e nomes em português: `fiscal`, `payments`, `documents-pdf`, `digital-signature`, `transparency`, `infrastructure`. **Diverge do exemplo da spec**, que usa `pagamentos`. |
| 5 | Descrições | Baseadas na descrição de cada repositório no GitHub (consultada em 28/10/2026); as de sped-nfe e laravel-boleto vêm da spec. `language: PHP` em todos, conforme o GitHub. `replaces` e `tags` só nos dois projetos que a spec já define. |
| 6 | Enums de `health` e formato de erro | Aprovados como descritos acima. |
| 7 | Release recente | `release_max_age_months: 12`. |
| 8 | `validate.yml` | Entra no M0. |

# Plano do M3 — Página (demo)

Status: implementado.

## Requisitos cobertos

| ID | O que entra |
| --- | --- |
| RF-05 | `bin/radar build` gera `public/index.html`, `public/style.css` e `public/snapshot.json`: projetos por categoria, os dois selos, link para o repositório e data da coleta. Sem JavaScript. |
| RNF-01 | HTML semântico (landmarks, títulos em ordem, link para pular ao conteúdo), foco visível, contraste ≥ 4.5:1 nos dois temas, selos com texto e ícone. Checagem automática com pa11y no CI (M4). |
| RNF-02 | Toda a interface em português |
| RNF-03 | Sem JavaScript, sem fontes externas, página com menos de 200 KB |
| RNF-04 | Sem scripts de terceiros, cookies ou analytics; só números agregados, nenhum nome ou login |
| Nice-to-have | Link "Issues para começar" por projeto (label `good first issue`) |

## Conteúdo da página

1. Cabeçalho: o que é o Radar e "Dados coletados em DD/MM/AAAA".
2. **Onde ajudar**: projetos com selo "Precisa de mãos" que não estão arquivados.
3. Uma seção por categoria (as vazias convidam a sugerir projetos).
4. **Como ler os selos**: regras com os números de `config/health.yaml`, nunca fixos no template.
5. **Sugira um projeto** e rodapé com licenças e o link para `snapshot.json`.

Cada projeto mostra: nome (link), descrição, linguagem, o que substitui, selos de Atividade e Sustentação,
"Última alteração em DD/MM/AAAA" quando não há alterações na janela, data do último release,
commits e pessoas na janela (só números) e licença.

## Decisões fora da spec

- URL do repositório do Radar vem de `RADAR_REPOSITORY_URL` (padrão `https://github.com/IEwerthonDev/harpia-radar`), para a migração para a organização não exigir mudança de código.
- Licença `NOASSERTION` aparece como "Licença não identificada automaticamente".
- `open_issues` não aparece na página (inclui PRs e pode soar como cobrança).
- Projeto com erro aparece sem selos, com a frase "Não foi possível atualizar os dados deste projeto na última coleta."
